# 43-02: Specific Action Feedback

## Objective
Replace generic "Working..." messages with specific descriptions of what MARO is actually doing.

## Current State
- Task titles exist in `Task.title` field but are human-readable summaries
- `build_task_plan_blocks()` shows task titles in the list
- No granular "currently doing X" feedback during execution

## Problem
During long operations, users see the task as "RUNNING" but don't know what step is happening. For example, "Generate stories" doesn't tell you if MARO is parsing requirements, calling the LLM, or waiting for Jira.

## Solution
Add an `active_step` field to track and display the current action within a task.

## Tasks

### 1. Add active_step field to Task schema
**File:** `src/schemas/task_plan.py`

Add optional field to Task:
```python
active_step: Optional[str] = None  # Current action: "Parsing requirements", "Calling Jira API"
```

### 2. Update status card to show active step
**File:** `src/slack/blocks/task_plan.py`

In `build_task_plan_blocks()`, for RUNNING tasks:
- Show `active_step` if set: `2) :arrows_counterclockwise: *BUILD*: Generate stories — Parsing requirements`
- Fall back to title if no active_step

### 3. Add set_active_step method to Task
**File:** `src/schemas/task_plan.py`

Helper method for setting step during execution:
```python
def set_active_step(self, step: str) -> None:
    self.active_step = step
```

### 4. Update task executors to report steps
**File:** `src/graph/nodes/task_executor.py` and related

Add step reporting at key points:
- Before LLM call: "Analyzing request"
- Before Jira API: "Updating Jira"
- Before batch operation: "Processing item 3/12"

### 5. Wire step updates through TaskStatusUpdater
**File:** `src/slack/task_status_updater.py`

Add method to update step without full card refresh:
```python
async def update_step(self, plan_id: str, task_id: str, step: str) -> None:
```
This should respect throttling but ensure step changes are visible.

## Acceptance Criteria
- [ ] Running tasks show what step they're on
- [ ] Step text is concise (<40 chars)
- [ ] Steps update in real-time (within throttle limits)
- [ ] No performance impact from frequent step updates
