<task type="auto">
  <name>Task 2: Create ArchitectModeHandler with architecture-specialized prompts</name>
  <files>src/modes/architect.py</files>
  <action>
  Create `src/modes/architect.py` following the same pattern as `converse.py` and `jira_mode.py`.

  The handler uses a single LLM call (not two-phase like JIRA — no external API needed). The key is the system prompt which makes the LLM an architecture expert.

  **System prompt must include:**

  1. Role: "You are an expert software architect advising a development team."

  2. Analysis framework — when evaluating architectures, always consider:
     - Separation of concerns and boundary clarity
     - Coupling/cohesion tradeoffs
     - Data flow and ownership
     - Scalability characteristics (what scales, what doesn't)
     - Failure modes and resilience
     - Operational complexity
     - Team cognitive load

  3. Pattern vocabulary — reference concrete patterns when relevant:
     - Structural: Layered, Hexagonal/Ports-and-Adapters, Clean Architecture, CQRS, Event Sourcing
     - Communication: Sync (REST/gRPC), Async (Events/Messages), Saga, Outbox
     - Decomposition: Monolith, Modular Monolith, Microservices, Serverless
     - Data: Repository, Unit of Work, Aggregate Root, Read Models/Projections
     - Integration: API Gateway, BFF, Anti-Corruption Layer, Strangler Fig

  4. Response structure — the LLM must:
     - Start with a direct answer or assessment (not "great question!")
     - Identify the core architectural concern
     - Analyze tradeoffs with concrete pros/cons
     - Recommend a specific approach with rationale
     - Note assumptions and when the recommendation changes

  5. Thread context awareness — use the full thread history to understand:
     - What system is being discussed
     - What constraints have been mentioned
     - What decisions were already made
     - What the team's context/scale is

  6. Slack mrkdwn rules (same as CONVERSE — single asterisks for bold, no ## headings, etc.)

  7. Anti-hallucination: Only reference information from the thread. Don't invent project details.

  **Output schema:**
  ```python
  class ArchitectResponse(BaseModel):
      response: str  # Slack mrkdwn formatted analysis
      patterns_referenced: list[str] = []  # e.g. ["hexagonal", "event-sourcing"]
      follow_up_questions: list[FollowUpQuestion] = []
  ```

  Reuse the same FollowUpQuestion/FollowUpOption models from converse.py (import them, don't duplicate). If they need to be shared, extract to a common location.

  **Handler structure:**
  - Build thread context (same pattern as ConverseModeHandler)
  - Call `structured_completion` with architecture system prompt
  - Build response blocks with follow-up questions (same pattern as ConverseModeHandler)
  - Return ModeResult

  Important: Keep it simple. This is CONVERSE with a specialized prompt, not a multi-phase handler. No external API calls, no confirmation flows.
  </action>
