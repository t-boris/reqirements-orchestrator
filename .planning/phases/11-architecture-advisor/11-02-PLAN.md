<objective>
Enrich the DecisionContent model with optional architecture metadata so ADRs created from ARCHITECT mode carry patterns and tradeoffs through the full decision lifecycle (pinned messages, Jira sync, dashboard).

These fields need to flow through DecisionContent, be persisted in events, and be displayed in pinned ADR messages. Without this, the architecture metadata from ARCHITECT would be lost when the ADR is recorded.

Output: Enriched DecisionContent with optional fields, updated ADR blocks to display patterns/tradeoffs, serialization compatibility.
