# Phase 28 Plan 06: Structure Feedback UI

**Objective:** Show draft structure after changes and implement version-bound approval buttons (R8, R9).

**Mantra:** After every structural mutation, the user must see what they have.

---

## Requirements Mapping

| Requirement | Description | Implementation |
|-------------|-------------|----------------|
| R8 | After each Draft form change, bot must show the new form | Structure visualization in `draft_structure.py` |
| R9 | Draft must be versioned - buttons bound to version | Version in button payload, stale button detection |

## DoD Tests

- **T1:** User says "Split into epics" → Bot shows new structure with items listed
- **T4:** Show preview (version=3), User transforms (version=4), Old approve button → "Outdated, please review new structure"

---

## Analysis

### Current State

1. **Button version binding** (Phase 27.4):
   - `build_draft_preview_blocks_with_hash()` includes `state_version` in button payloads
   - `approval_validator.py` checks `state_version != current_state_version`
   - Returns "This preview is outdated. Please review the updated version."

2. **Draft preview blocks** (`src/slack/blocks/draft.py`):
   - Shows TicketDraft fields: title, problem, solution, AC
   - No support for StructuredDraft's multi-item structure
   - No visualization of kind/scope/lifecycle

3. **Transform handler** (`src/graph/nodes/draft_transform.py`):
   - Returns `action="transform_applied"` after mutation
   - Does NOT show updated structure to user
   - Handler needs to render new structure after mutation

### What Needs to Change

1. **Structure visualization** (R8): Create blocks that show StructuredDraft structure
   - Show kind (SINGLE_ITEM vs PLAN)
   - Show scope (SINGLE, EPICS_ONLY, FULL_PLAN)
   - Show lifecycle state
   - List all items with type, title, status
   - Show parent-child relationships for stories under epics

2. **Version-bound structure** (R9): Extend existing version binding
   - Include `draft.version` in structure preview buttons
   - Detect stale structure previews after transforms
   - Show "Outdated" message for stale approve buttons

3. **Post-transform feedback**: After each mutation, dispatch handler posts structure

```python
"""Slack blocks for StructuredDraft structure visualization.

Shows the draft's typed structure including kind, scope, lifecycle,
and item hierarchy after mutations (R8).
"""
from typing import Any, Optional
from src.schemas.structured_draft import (
    StructuredDraft, DraftKind, DraftScope, DraftLifecycle,
    DraftItem, DraftItemStatus
)
from src.schemas.draft import IssueType
import json


def build_structure_blocks(
    draft: StructuredDraft,
    show_actions: bool = True,
    include_version: bool = True,
) -> list[dict]:
    """Build Slack blocks showing StructuredDraft structure.

    R8: After each Draft form change, bot must show the new form.

    Args:
        draft: StructuredDraft to visualize
        show_actions: Whether to include approve/edit buttons
        include_version: Whether to show version info in footer

    Returns:
        List of Slack block dicts
    """


def _build_header_block(draft: StructuredDraft) -> dict:
    """Build header showing kind and scope."""
    kind_emoji = "📋" if draft.kind == DraftKind.PLAN else "📝"
    scope_label = {
        DraftScope.SINGLE: "Single Item",
        DraftScope.EPICS_ONLY: "Epics Only",
        DraftScope.FULL_PLAN: "Full Plan",
    }.get(draft.scope, draft.scope.value)

    lifecycle_emoji = {
        DraftLifecycle.EMPTY: "⬜",
        DraftLifecycle.SINGLE_ITEM: "📝",
        DraftLifecycle.PLAN: "📋",
        DraftLifecycle.PLAN_REFINED: "✨",
        DraftLifecycle.APPROVED: "✅",
        DraftLifecycle.COMMITTED: "🚀",
    }.get(draft.lifecycle, "❓")

    return {
        "type": "header",
        "text": {
            "type": "plain_text",
            "text": f"{kind_emoji} Draft Structure - {scope_label}",
            "emoji": True,
        },
    }


def _build_item_block(item: DraftItem, index: int, is_child: bool = False) -> dict:
    """Build block for a single draft item."""
    type_emoji = {
        IssueType.EPIC: "🎯",
        IssueType.STORY: "📖",
        IssueType.TASK: "✔️",
        IssueType.BUG: "🐛",
    }.get(item.issue_type, "📄")

    status_emoji = {
        DraftItemStatus.PROPOSED: "🔵",
        DraftItemStatus.APPROVED: "🟢",
        DraftItemStatus.COMMITTED: "✅",
    }.get(item.status, "⚪")

    indent = "    └─ " if is_child else ""
    title_text = item.title or "_No title_"

    return {
        "type": "section",
        "text": {
            "type": "mrkdwn",
            "text": f"{indent}{status_emoji} {type_emoji} *{item.issue_type.value.upper()}:* {title_text}",
        },
    }


def _build_action_buttons(draft: StructuredDraft) -> dict:
    """Build approve/edit action buttons with version binding."""
    payload = {
        "draft_id": draft.id,
        "version": draft.version,
    }

    return {
        "type": "actions",
        "elements": [
            {
                "type": "button",
                "text": {"type": "plain_text", "text": "Approve Structure", "emoji": True},
                "value": json.dumps(payload),
                "action_id": "approve_structure",
                "style": "primary",
            },
            {
                "type": "button",
                "text": {"type": "plain_text", "text": "Edit Structure", "emoji": True},
                "value": json.dumps(payload),
                "action_id": "edit_structure",
            },
        ],
    }


def _build_version_context(draft: StructuredDraft) -> dict:
    """Build footer context with version info."""
    return {
        "type": "context",
        "elements": [{
            "type": "mrkdwn",
            "text": f"Version {draft.version} | {len(draft.items)} items | {draft.lifecycle.value}",
        }],
    }
```

Structure visualization shows:

```python
async def handle_edit_structure(
    ack: AsyncAck,
    body: dict,
    client: AsyncWebClient,
) -> None:
    """Handle edit_structure button click.

    Prompts user to describe desired changes to draft structure.
    """
    await ack()

    channel_id = body["channel"]["id"]
    user_id = body["user"]["id"]
    thread_ts = body["message"].get("thread_ts") or body["message"]["ts"]

    # Post prompt for user to describe changes
    await client.chat_postMessage(
        channel=channel_id,
        thread_ts=thread_ts,
        text="What changes would you like to make to the draft structure? You can say things like:\n"
             "• \"Split this into multiple epics\"\n"
             "• \"Add a story for authentication\"\n"
             "• \"Merge the first two items\"\n"
             "• \"Change scope to epics only\"",
    )
```

## Decisions

- **Structure format:** Text-based blocks (not complex visual diagrams) - simpler, mobile-friendly
- **Item hierarchy:** Indent stories under epics with "└─" prefix
- **Version binding:** Reuse existing payload JSON format from Phase 27.4
- **Stale detection:** Ephemeral message (private) rather than in-thread (public)
- **Edit flow:** Simple text prompt, user response routes to DRAFT_TRANSFORM intent

---

## Risk Assessment

| Risk | Mitigation |
|------|------------|
| Block limit exceeded for large plans | Truncate to 10 items, show "+N more" |
| Version race condition | Ephemeral message is advisory, not blocking |
| Edit prompt confusion | Clear examples in prompt text |
