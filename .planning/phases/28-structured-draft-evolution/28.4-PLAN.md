# Phase 28 Plan 04: Lifecycle State Machine

**Objective:** Enforce lifecycle transitions and make validation depend on draft form (R5, R6).

**Mantra:** Bot asks lifecycle-appropriate questions - decomposition for PLANs, acceptance criteria for STORYs.

---

## Requirements Mapping

| Requirement | Description | Implementation |
|-------------|-------------|----------------|
| R5 | Draft must have lifecycle - Cannot ask AC while in PLAN stage | Lifecycle-aware question selection in decision.py |
| R6 | Validation depends on Draft form | Form-dependent validation rules in validation.py |

## DoD Tests

- **T2:** Draft in PLAN stage → bot asks about decomposition (not acceptance criteria). Only when item_type=STORY does bot ask AC.
- **T5:** Epic draft → validate goal/scope. Story draft → validate AC. Plan draft → validate item count/decomposition logic.

---

## Analysis

### Current State

1. **StructuredDraft** (28.1) has:
   - `lifecycle: DraftLifecycle` field with EMPTY/SINGLE_ITEM/PLAN/PLAN_REFINED/APPROVED/COMMITTED states
   - `can_transition_to()` method validating transitions
   - `_VALID_TRANSITIONS` dict defining allowed state changes

2. **validation.py** currently:
   - Uses same validation for all drafts (title, problem, acceptance_criteria)
   - Always requires acceptance_criteria regardless of issue type
   - No awareness of StructuredDraft lifecycle

3. **decision.py** currently:
   - Asks same questions regardless of draft stage
   - No lifecycle-aware question prioritization
   - Uses TicketDraft, not StructuredDraft

### What Needs to Change

1. **Form-dependent validation** (R6):
   - EPIC: Validate goal, scope - NOT acceptance criteria
   - STORY: Validate acceptance criteria (at least one)
   - PLAN: Validate item count (>1), logical decomposition

2. **Lifecycle-aware questions** (R5):
   - EMPTY/SINGLE_ITEM with EPIC type: Ask about goal, scope, decomposition options
   - PLAN stage: Ask about decomposition, item structure - NOT AC
   - Only STORY items: Ask about acceptance criteria

### Task 1: Add form-dependent validation rules

**File:** `src/graph/nodes/validation.py`

**Changes:**

1. Add `_get_validation_rules_for_type()` function that returns different required fields based on issue type:

```python
def _get_validation_rules_for_type(issue_type: IssueType | None) -> dict:
    """Get validation rules based on issue type.

    R6: Validation depends on Draft form.
    - EPIC: goal/scope required, AC NOT required
    - STORY: title, problem, AC required
    - TASK/BUG: title, problem required, AC optional
    """
    if issue_type == IssueType.EPIC:
        return {
            "required": ["title", "problem"],  # problem = goal
            "optional": ["acceptance_criteria"],  # NOT required for epics
            "weight": {"title": 30, "problem": 50, "scope": 20},
        }
    elif issue_type == IssueType.STORY:
        return {
            "required": ["title", "problem", "acceptance_criteria"],
            "optional": [],
            "weight": {"title": 25, "problem": 25, "acceptance_criteria": 50},
        }
    else:  # TASK, BUG
        return {
            "required": ["title", "problem"],
            "optional": ["acceptance_criteria"],
            "weight": {"title": 40, "problem": 60},
        }
```

### Task 3: Enforce lifecycle transitions on state changes

**File:** `src/graph/nodes/validation.py` and `src/slack/handlers/dispatch.py`

**Changes:**

1. Add `transition_lifecycle()` helper that enforces valid transitions:

```python
def transition_lifecycle(
    draft: StructuredDraft,
    target: DraftLifecycle,
    user_id: str,
) -> bool:
    """Transition draft to new lifecycle state with validation.

    Returns True if transition succeeded, False if invalid.
    Logs the transition to change_log.
    """
    if not draft.can_transition_to(target):
        logger.warning(
            "Invalid lifecycle transition",
            extra={
                "from": draft.lifecycle.value,
                "to": target.value,
            }
        )
        return False

    old_lifecycle = draft.lifecycle
    draft.lifecycle = target
    draft.log_change(
        action="lifecycle_transition",
        user_id=user_id,
        details={"from": old_lifecycle.value, "to": target.value},
    )
    return True
```

2. Add automatic lifecycle advancement in validation:
   - All items APPROVED → lifecycle can advance to APPROVED
   - All items COMMITTED → lifecycle advances to COMMITTED
