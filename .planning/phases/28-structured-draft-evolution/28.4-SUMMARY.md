## Key Changes

### 1. Form-Dependent Validation (validation.py)

**New Functions:**
- `_get_validation_rules_for_type(issue_type)` - Returns validation rules based on issue type
- `validate_structured_draft(draft)` - Validates StructuredDraft based on lifecycle and type
- `transition_lifecycle(draft, target, user_id)` - Enforces valid lifecycle transitions with logging

**Validation Rules:**
- **EPIC**: title, problem required; AC optional
- **STORY**: title, problem, AC required
- **TASK/BUG**: title, problem required; AC optional
- **PLAN kind**: requires 2+ items

**Updated Functions:**
- `rule_based_validation()` - Now uses type-aware rules
- `validation_node()` - Checks for `structured_draft` first

### 2. Lifecycle-Aware Question Selection (decision.py)

**New Functions:**
- `_filter_questions_by_lifecycle(missing_fields, lifecycle, issue_type)` - Filters out inappropriate questions
- `_get_lifecycle_questions(draft, missing_fields)` - Wrapper for StructuredDraft

**Behavior:**
- PLAN stage: Bot asks about decomposition, NOT acceptance criteria
- EPIC type: Bot skips AC questions
- STORY type: Bot asks all required fields including AC

**Updated Functions:**
- `prioritize_issues()` - Now accepts lifecycle and issue_type parameters
- `decision_node()` - Extracts lifecycle context and passes to prioritize_issues

### 3. Lifecycle Transition Enforcement (draft.py)

**Pre-Approval Check:**
- Rejects approvals on COMMITTED drafts (terminal state)
- Returns ephemeral message explaining the draft is already committed

**Post-Creation Advancement:**
- Marks all items as COMMITTED with jira_key set
- Transitions lifecycle: SINGLE_ITEM -> APPROVED -> COMMITTED
- Logs transitions to change_log for audit trail
