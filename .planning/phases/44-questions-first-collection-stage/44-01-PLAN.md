Create new schema module with:

1. TriageSignal enum - what context signals were detected:
   - HAS_DRAFT: Active draft exists
   - HAS_ANCHOR: Thread has anchor (workitem/decision)
   - HAS_JIRA_KEY: Message mentions Jira ticket
   - HAS_EXPLICIT_MODE: User explicitly said "review", "create", "decide"
   - HAS_TOPIC: Clear subject/topic extractable
   - LOW_CONFIDENCE_MODE: Stage 1 mode score < 0.6

2. TriageGap enum - what's missing:
   - UNKNOWN_MODE: Can't determine BUILD vs THINK vs DECIDE
   - UNKNOWN_SCOPE: Don't know if epic/story/task
   - UNKNOWN_TARGET: No clear subject (what are we working on?)
   - AMBIGUOUS_INTENT: Multiple interpretations possible
   - MISSING_TOPIC: For review, topic unclear

3. TriageContext dataclass:
   - signals: set[TriageSignal]
   - gaps: set[TriageGap]
   - completeness_score: float (0-1, computed from signals)
   - suggested_questions: list[str] (gap-specific question hints)
   - fast_path: bool (True if completeness > threshold)

4. COMPLETENESS_THRESHOLD = 0.7 (configurable)

Pattern: Similar to PreGateOutput but focused on context completeness, not safety.

<task type="auto">
  <name>Task 2: Create triage gate module</name>
  <files>src/graph/triage_gate.py</files>
  <action>
Create triage gate module that detects context signals and gaps:

1. detect_signals(state, message) -> set[TriageSignal]:
   - Check state.draft / state.structured_draft → HAS_DRAFT
   - Check state.anchor → HAS_ANCHOR
   - Regex for JIRA_KEY_PATTERN in message → HAS_JIRA_KEY
   - Check for explicit mode keywords ("review this", "create", "decide") → HAS_EXPLICIT_MODE
   - Simple topic extraction (nouns after "about", "for", "on") → HAS_TOPIC

2. detect_gaps(signals, message) -> set[TriageGap]:
   - If not HAS_EXPLICIT_MODE and not HAS_DRAFT → UNKNOWN_MODE
   - If not HAS_ANCHOR and not HAS_JIRA_KEY and not HAS_TOPIC → UNKNOWN_TARGET
   - If short message (<10 words) and no signals → AMBIGUOUS_INTENT

3. compute_completeness(signals, gaps) -> float:
   - Start with 1.0
   - Subtract 0.2 for UNKNOWN_MODE
   - Subtract 0.3 for UNKNOWN_TARGET
   - Subtract 0.2 for AMBIGUOUS_INTENT
   - Subtract 0.1 for MISSING_TOPIC
   - Clamp to [0.0, 1.0]

4. check_triage_needed(state, message) -> TriageContext:
   - Calls detect_signals, detect_gaps, compute_completeness
   - Sets fast_path = (completeness >= COMPLETENESS_THRESHOLD)
   - Generates suggested_questions from gaps

5. Gap-to-question mapping:
   - UNKNOWN_MODE → "What would you like to do? [Create work items] [Get architectural review] [Record a decision]"
   - UNKNOWN_TARGET → "What is this about? (provide topic or paste a ticket key)"
   - UNKNOWN_SCOPE → "What type of work item? [Epic] [Story] [Task]"

Keep it deterministic (no LLM calls). This is a fast gate before LLM classification.
  </action>
