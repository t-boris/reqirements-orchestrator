## Milestone Summary

**Key Decisions:**
- Decision: Store decision data as JSON in action.value (Rationale: Decouple block format from data flow)
- Decision: Fixed action_id with entity ID in value (Rationale: Exact string match vs regex)
- Decision: JiraNotificationProjection via outbox (Rationale: Decouple side effects from handlers)
- Decision: Approvals preserved on amendment (Rationale: Domain intentionally keeps approvals through content changes)
- Decision: adr_message_ts stored in entities_view column (Rationale: Read model consistency with aggregate)

**Issues Resolved:**
- ISS-001: Pinned ADR messages have no lifecycle UI
- ISS-003: Block parsers brittle — coupled to mrkdwn format
- ISS-004: Entity IDs embedded in action_id instead of value
- ISS-005: Action handlers do too much — Jira calls block user response
- ISS-006: Dashboard does not distinguish Draft from Proposed decisions
- ISS-007: Dashboard truncation has no overflow indicator
- ISS-008: Amendment projection doesn't update approvals or adr_message_ts

**Issues Deferred:**
- ISS-002: adr_message_ts field on work item entities is dead weight (Low ROI, would require event migration)

**Technical Debt Incurred:**
- ISS-002 remains — adr_message_ts on work item entities is unused but harmless
