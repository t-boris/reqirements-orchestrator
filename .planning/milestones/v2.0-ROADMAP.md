# Milestone v2.0: MARO 2.0

**Status:** SHIPPED 2026-02-02
**Phases:** 1-7
**Total Plans:** 39

## Overview

Complete rewrite of MARO from v1.x to an event-sourced architecture. The journey takes us from foundation (domain model, event store) through Slack integration, intent classification, entity lifecycle management, process orchestration, and finally Jira projection. Each phase builds on the previous, culminating in a deployable system that transforms conversations into work items.

## Milestone Summary

**Key Decisions:**
- Event sourcing over CRUD (single source of truth, audit trail)
- Sum types for entities (make illegal states unrepresentable)
- 4 SuperModes only (simplified from 13 intents)
- Channel as aggregate root (consistent boundaries)
- Gemini as default LLM (cost-effective)
- Mandatory duplicate detection before Jira create
- Field ownership model for conflict detection

**Issues Resolved:**
- None (greenfield development)

**Issues Deferred:**
- None

**Technical Debt Incurred:**
- Slack handlers have placeholder TODOs for full entity wiring
- Some flows return hardcoded responses pending full integration
